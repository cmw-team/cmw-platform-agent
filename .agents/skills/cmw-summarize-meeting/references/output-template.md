# Шаблон summary встречи

Передай в `content` вызова `save_meeting_markdown` полный Markdown следующего
вида:

```markdown
# Итоги встречи

Источник: `<точное исходное имя файла>`, `<имена частей в порядке>` или
`транскрипт пользователя`

## Краткий итог

- ...
- ...

## Темы обсуждения

### [Название темы]

...

### [Название следующей темы]

...

## Решения и договорённости

- ...

## Предположительные шаги

| Действие | Ответственный | Срок |
|---|---|---|
| ... | ... | ... |

## Открытые вопросы и риски

- ...
```

Все пять смысловых разделов присутствуют всегда. Количество выводов и тем
определяется содержанием разговора, а не фиксированной квотой.

Если сведений для раздела нет, используй явную пометку:

- `Решения не зафиксированы`;
- `Предположительные шаги не зафиксированы`;
- `Открытые вопросы и риски не зафиксированы`.

Для отсутствующего ответственного или срока используй `Не указан`.

Если транскрипция не содержит надёжной атрибуции спикеров:

- не определяй говорящего по порядку сегментов;
- не связывай `я` и `ты` с упомянутыми рядом именами;
- не угадывай, кто владеет интерфейсом, должен показать материалы или выполнить
  настройку;
- сохраняй понятное действие, но ставь `Не указан` в столбце
  `Ответственный`;
- формулируй неоднозначное взаимодействие нейтрально, например:
  `Совместно проверить интерфейс и согласовать его настройку`.

Имя допустимо в столбце `Ответственный` только при прямом назначении действия
этому человеку в тексте, например: `Максим подготовит таблицу`.

## Инварианты

1. Темы сгруппированы по смыслу, а не по порядку отдельных реплик.
2. Решением называется только явно согласованный результат.
3. Предположительные шаги не смешиваются с идеями и открытыми вопросами.
4. Неизвестные ответственные и сроки не угадываются.
5. Участникам не приписываются слова без надёжного основания.
6. Сегменты без диаризации не используются для восстановления говорящих.
7. Таймкоды не добавляются.
8. Summary не содержит полного транскрипта, сырого JSON, стоимости, токенов,
   Base64 или внутренних путей.

Полный транскрипт не включай в `content` summary: для него выполни отдельный
вызов `save_meeting_markdown` с `artifact_type: "transcript"`.
