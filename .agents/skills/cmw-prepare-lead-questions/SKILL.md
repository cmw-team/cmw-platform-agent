# Подготовка квалификационных вопросов по лиду

## Цель

Подготовь для сейла 10 открытых квалификационных вопросов, которые:

- соответствуют компании, отрасли и запросу лида;
- не повторяют уже известные ответы;
- помогают подтвердить проблему, последствия, ожидаемый результат и основания
  для продолжения пресейла;
- используют терминологию компании и отрасли умеренно и только при достаточных
  основаниях.

Не превращай вопросы в техническое обследование и не проектируй детальное
решение. Это этап прояснения боли и потребности.

## Обязательные материалы

Перед составлением вопросов прочитай:

1. [references\brief-short.md](references\brief-short.md) — стартовые 10 вопросов.
2. [references\question-bank.md](references\question-bank.md) — банк замен.
3. [references\output-example.md](references\output-example.md) — эталон формата.

При использовании поиска дополнительно прочитай:

- [references\knowledge-base-search.md](references\knowledge-base-search.md);
- [references\web-research.md](references\web-research.md).

Пользователь не обязан прикладывать брифы: используй встроенные references.

## Доступные входные данные

Извлеки всё, что присутствует:

- ID лида;
- email — только как источник корпоративного домена для веб-поиска;
- название компании;
- корпоративный домен;
- отрасль;
- текст запроса лида;
- дополнительные комментарии сейла;
- транскрипт разговора или встречи.

Не требуй все поля одновременно.

## Получение данных CRM

### Если есть ID лида

Используй `get_record_values` с ID и только с заранее согласованными системными
именами атрибутов.

Список атрибутов пока не утверждён:

```text
TODO_CRM_ATTRIBUTE_SYSTEM_NAMES
```

Пока список не заполнен, не угадывай системные имена атрибутов и не вызывай
tool с выдуманными значениями. Используй данные сообщения и транскрипта либо
попроси пользователя предоставить недостающую информацию.

### Если нет ID, но есть email

Если передан email, извлеки из него домен. Корпоративный домен используй только
для идентификации компании в веб-поиске. Не используй личные почтовые домены
для определения компании.

Если компания и запрос уже понятны, не блокируй подготовку вопросов.

Если данных недостаточно, попроси ID лида либо название компании и запрос.
Уточнение задаётся до итоговой десятки и не является частью результата.

## Приоритет источников

При противоречиях используй следующий приоритет:

1. уточнение пользователя в текущем диалоге;
2. прямые слова клиента из транскрипта;
3. данные карточки CRM;
4. официальный сайт компании;
5. надёжные внешние источники;
6. отраслевые гипотезы.

Отделяй подтверждённые сведения от предположений. Не встраивай предположение
в вопрос как установленный факт.

## Рабочий процесс

### Шаг 1. Нормализуй контекст

Собери рабочую карточку:

```text
Компания:
Домен:
Отрасль:
Запрос:
Известные ответы:
Неясности:
```

Эта карточка нужна для внутренней работы. Не показывай её в итоговом ответе.

### Шаг 2. Определи, достаточно ли данных

Попробуй восстановить компанию и запрос из сообщения, CRM и транскрипта.

Задай уточняющий вопрос, если:

- компанию невозможно однозначно определить;
- запрос отсутствует во всех источниках;
- найдено несколько подходящих компаний;
- источники содержат критичное противоречие.

Не задавай уточнение, если оно лишь слегка улучшит формулировки и без него
можно подготовить полезные вопросы.

### Шаг 3. Извлеки известные ответы

Отметь темы, которые уже подтверждены:

- контекст инициативы;
- текущий способ работы;
- конкретная проблема;
- последствия;
- предыдущие попытки;
- ожидаемый результат;
- критерии успеха;
- срочность и срок;
- владелец задачи, инициатор и ЛПР;
- бюджет, ограничения и риски;
- ожидаемый следующий шаг.

Не задавай вопрос повторно только ради заполнения формального списка.
Допускается уточняющий вопрос, если известный ответ неполный, противоречивый
или требует измеримого критерия.

### Шаг 4. Исследуй компанию

Используй `web_search` по правилам из
[references\web-research.md](references\web-research.md).

Ищи только сведения, которые помогают:

- понять деятельность и отраслевую терминологию;
- проверить идентичность компании;
- понять вероятный контекст запроса;
- сделать вопросы конкретнее, не превращая гипотезы в факты.

### Шаг 5. При необходимости проверь базу знаний

Используй `get_knowledge_base_articles` по правилам из
[references\knowledge-base-search.md](references\knowledge-base-search.md),
если запрос содержит платформенные, процессные или интеграционные требования,
и знание документации поможет задать более содержательный вопрос.

База знаний не нужна для каждого лида. В этом skill она помогает сформулировать
вопросы, но не должна превращать результат в презентацию возможностей продукта.

### Шаг 6. Возьми короткий бриф за основу

Начни с 10 вопросов из `brief-short.md`.

Для каждого вопроса проверь:

1. Есть ли уже достоверный ответ?
2. Подходит ли вопрос к запросу лида?
3. Продвигает ли вопрос квалификацию сделки?
4. Не дублирует ли он другой вопрос?

### Шаг 7. Замени слабые вопросы

Если ответ уже известен, вопрос неприменим или малоценен:

1. Найди в `question-bank.md` вопрос по той же теме.
2. Если вся тема уже закрыта, выбери вопрос по наиболее важному незакрытому
   полю квалификации.
3. Не используй банк как источник для механического добора количества.
4. Не создавай два вопроса, запрашивающих одну и ту же информацию.

### Шаг 8. Адаптируй формулировки

Используй название компании и отраслевую терминологию умеренно.

Хорошая адаптация:

> Как сейчас руководство видит задолженность по странам, юрлицам и покупателям?

Плохая адаптация:

> Как ваша инновационная международная логистическая экосистема FlexWay
> осуществляет end-to-end visibility дебиторской задолженности?

Не перегружай вопрос названиями продуктов и профессиональным жаргоном.

## Контракт результата

Верни:

- ровно 10 вопросов;
- один вопрос на строку;
- без заголовка;
- без вступления;
- без нумерации и маркеров;
- без пояснений, источников и заключения;
- каждый вопрос должен заканчиваться знаком `?`.

Перед ответом проверь:

- вопросов ровно 10;
- нет смысловых дублей;
- нет вопросов с уже известным полным ответом;
- вопросы открытые, а не предполагающие ответ «да/нет»;
- нет неподтверждённых фактов;
- терминология используется умеренно;
- вопросы подходят для живого разговора, а не для чтения анкеты.

## Конфиденциальность

Не отправляй в веб-поиск:

- внутренние комментарии CRM;
- транскрипт целиком;
- личные email и телефоны;
- бюджет и непубличные детали сделки;
- персональные данные участников.

Для веб-поиска используй только название компании, официальный корпоративный
домен, отрасль и общедоступное описание направления деятельности.
